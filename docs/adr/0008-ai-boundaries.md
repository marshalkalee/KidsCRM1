# ADR-0008: Место ИИ в продукте и граница «что можно показывать модели»

## Статус

Принято частично (TRU-156, 05.10.2026):

- **имена — вариант (а), псевдонимы:** решение Анель от 05.10.2026, сделано —
  `ai/pseudonyms.py`;
- **ключ API** — пока личный ключ Анель, заменим ключом на юрлицо, когда его
  получим;
- **решение по каждой функции** — открыто (см. «Нужно решить»).

## Контекст

В `backend/domains/platform/ai/` с сентября работает ИИ-модуль, которого не
было ни в одном тикете: 11 функций на экранах и чат на главной. Модель
внешняя — OpenAI (`gpt-4o`, `gpt-4o-mini`) или Claude по `AI_PROVIDER`, ключ
личный, расход нигде не считается.

Ограничения:

- **ТЗ п. 8 и 10.3:** персональные данные детей во внешние API не передаются,
  только обезличенные агрегаты.
- **Закон РК «О персональных данных и их защите», ст. 12:** база ПДн граждан
  хранится в Казахстане. Передача за границу допускается в страны с
  достаточной защитой или с согласия субъекта. Серверы OpenAI и Anthropic
  находятся вне Казахстана.

## Что уходит в модель сейчас

Установлено тестом, а не описанием: `ai/tests_pd_flow.py` подменяет модель,
прогоняет каждую функцию на данных с метками и сверяет результат с описью
`ai/pd_inventory.py`. Новая функция или новое поле в запросе роняют тест,
пока опись не обновлена.

| Функция | Кто вызывает | Что уходит |
|---|---|---|
| Чат на главной (`chat`) | владелец, управляющий, администратор | вопрос, имя спрашивающего; через инструменты — **ФИО детей, даты рождения, ФИО родителей, долги, заявки** |
| Напоминания о долге/продлении (`reminders`) | владелец, управляющий, администратор | **имена детей и плательщиков**, суммы |
| Сообщение родителю по заявке (`lead_message`) | они же | **имя родителя и ребёнка**, статус, комментарии |
| «Перед звонком» (`child_brief`) | все сотрудники | **имя ребёнка**, посещаемость, деньги (если роли можно), заметки о звонках |
| Чистка файла импорта (`import_clean`) | владелец, управляющий, администратор | **весь файл клиентов**: ФИО, даты рождения, телефоны |
| Заявка из сообщения (`lead_from_text`) | они же | вставленный текст родителя: **имя, телефон** |
| Фото журнала (`attendance_photo`) | все, преподаватель — свои занятия | **фото журнала с рукописными именами**; список группы не уходит |
| Поиск словами, заметка о звонке, причина отказа | разные | только текст, который ввёл сотрудник |
| Подбор группы (`lead_groups`), план дня (`daily_plan`) | разные | без имён: возраст, счётчики, группы |

Чего нет нигде, и это проверено тестом:

- **Телефоны и почта из базы.** Телефон уходит, только если сотрудник сам
  вставил его в текст или файл.
- **Медицинские заметки.** Убраны из «Перед звонком» и из карточки ребёнка в
  чате 05.10.2026 в рамках этого тикета: это данные о здоровье, а для
  задач помощника они не нужны.

Вывод: **имена и даты рождения детей уходят за границу** в пяти функциях и в
чате. Требованию ТЗ п. 10.3 это не соответствует.

## Решение (предложено)

1. **Граница — по категориям, а не по функциям.** Нужно согласовать
   «можно / нельзя» по каждой категории данных:

   | Категория | Можно? |
   |---|---|
   | агрегаты и числа (заполняемость, конверсия, суммы по центру) | да |
   | справочники центра (филиалы, направления, группы, причины) | да |
   | текст, который сотрудник сам вставил ради задачи | да, с подсказкой в интерфейсе «уйдёт во внешний сервис» |
   | имена детей и родителей из базы | **нужно решить** — варианты ниже |
   | даты рождения | нет: модели хватает возраста |
   | телефоны, почта | нет, уже так |
   | медицинские заметки, причина ухода, согласие | нет, медицинские убраны |

2. **Имена — три варианта, выбирает заказчик:**
   - **а) Псевдонимы (рекомендуется).** Перед отправкой имена заменяются
     метками («Ребёнок 7», «Плательщик 3»), модель отвечает метками, на нашей
     стороне они заменяются обратно. Сотрудник видит ответ с именами, как
     сейчас, а наружу имена не уходят. Работает и для чата, и для
     напоминаний, и для сообщений родителю. Работа — около недели, слой
     агрегатов (TRU-158) строится по тому же принципу.
   - **б) Оставить как есть с письменным решением заказчика.** Это решение
     должен подписать заказчик, а в согласие родителей на обработку данных
     нужно добавить пункт о передаче внешнему ИИ-сервису. Риск по закону
     остаётся на центре.
   - **в) Выключить функции с именами** (чат, напоминания, сообщения, «Перед
     звонком», чистка импорта) до варианта (а).
3. **Любая новая отправка данных в модель** проходит через опись
   `pd_inventory.py` и её тест. Ревьюер сверяет изменение с таблицей пункта 1.
4. **Помощник только советует.** Он читает и предлагает, но ничего не меняет:
   не принимает оплаты, не пишет родителям, не трогает расписание. Это уже
   так (системный промпт чата, инструменты — только чтение), и это инвариант:
   расширение полномочий — отдельный ADR.

## Рекомендация по каждой функции

| Функция | Рекомендация |
|---|---|
| Чат на главной | оставить и развивать в M5 — после псевдонимов (2а) |
| Напоминания, сообщение родителю | оставить после псевдонимов |
| «Перед звонком» | оставить (медзаметки уже убраны), имена — после псевдонимов |
| Фото журнала | оставить под флагом центра; в согласии — пункт о фото журнала |
| Чистка файла импорта | под флагом: разово при подключении центра, с согласия центра на передачу файла |
| Заявка из сообщения, заметка о звонке, причина отказа, поиск, подбор группы, план дня | оставить: данных из базы нет или только обезличенные |

## Как сделаны псевдонимы (вариант «а»)

- **Что заменяется.** `ai/pseudonyms.py` берёт из базы центра имена детей,
  родителей и контактов заявок — полностью и по частям — и заменяет их в
  любом тексте перед отправкой метками `[N12]`. Ловятся и падежные формы с
  заглавной буквы («Исаевой Сафией»). Ответ модели проходит обратную замену.
- **Где включается.** Все функции идут через `services._ask_json(organization=…)`,
  где организация обязательна, так что мимо замены запрос не отправить. Чат
  маскирует историю, вопрос и ответы инструментов. Аргументы инструментов
  (`search q=[N1]`) возвращаются к нашему API с настоящими именами.
- **Метки чата** хранятся с перепиской (`AIConversation.pseudonyms`), поэтому
  у одного человека метка от вопроса к вопросу одна.
- **Чего не делаем.** Имена сотрудников не заменяются: это не данные клиентов,
  а модели нужно понимать, кто ответственный. Дата рождения в чат не уходит,
  модели хватает возраста.
- **Ограничения:**
  - имя, которого ещё нет в базе (новая заявка из вставленного текста, файл
    импорта нового центра), уходит как есть;
  - фото журнала уходит как есть;
  - падежная форма со строчной буквы не ловится;
  - имя в ответе — в именительном падеже («у Исаева Сафия долг»): модель не
    склоняет метку.
- **Проверка.** `ai/tests_pseudonyms.py` и `ai/tests_pd_flow.py`: имена и даты
  рождения из базы не уходят ни одной функцией и ни одним инструментом.
  Проверено и на живой модели (`gpt-4o`).

## Отвергнутые варианты

- **Описание вместо теста.** В статусе было «телефоны не уходят», а про имена
  и медзаметки — ничего. Опись, которую сверяет тест, не устаревает молча.
- **Свой сервер с открытой моделью ради ПДн.** Решает вопрос
  трансграничности, но требует 16+ млн ₸ или ~1 млн ₸/мес аренды и
  обслуживания. При нашей нагрузке это несоразмерно. Псевдонимы дают тот же
  результат для имён без своего железа.

## Последствия

- `ai/pd_inventory.py` и `ai/tests_pd_flow.py` — обязательная часть любого
  изменения в ИИ-модуле. Новый эндпоинт без записи в описи роняет CI.
- До решения по пункту 2 функции с именами работают как раньше, но риск
  зафиксирован (`docs/project-status.md`, п. 9).
- Варианты (а) и TRU-158 используют общий принцип: наружу уходят метки и
  числа, реальные данные остаются у нас.
