# WhatsApp по QR-коду (Evolution API)

Центр подключает свой обычный номер WhatsApp, отсканировав QR-код, как в
WhatsApp Web. После этого CRM сама пишет родителям с этого номера и
получает их ответы. Решение и риски описаны в
[ADR-0010, дополнение от 12.11.2026](adr/0010-whatsapp-provider.md).

## Как это устроено

```
CRM (backend, worker) ──http://evolution:8080──▶ Evolution API ──▶ WhatsApp
        ▲                                             │
        └──── https://<сайт>/api/v1/messaging/whatsapp/evolution/<секрет>/
```

- **Evolution API** — отдельный контейнер `evolution`
  (образ `evoapicloud/evolution-api:v2.3.7`). Наружу не открыт. Одно
  подключение (instance) = один номер.
- **Номер на центр или на филиал.** У каждого филиала может быть свой номер.
  Родителю пишем с номера филиала, где занимается его ребёнок; если у
  филиала номера нет — с номера центра или любого подключённого.
  Отвечаем с того номера, на который родитель написал.
- **Вебхук.** У каждого номера свой секретный адрес. События: номер
  подключился или отключился, входящее сообщение, доставлено или прочитано.
  CRM отвечает сразу, а разбирает событие в очереди (Celery).
- **Без шаблонов Meta и 24-часового окна.** Уходит обычный текст события
  (тот же, что в письме). Переписка с родителями свободная, в обе стороны;
  слово «стоп» в чате ничего не отключает (это правило только для Meta).
- **Пауза между сообщениями** с одного номера — `EVOLUTION_SEND_INTERVAL`
  секунд (по умолчанию 4). Если очередь длинная, сообщение ждёт своей
  очереди, а не уходит на почту.
- **Номер отключился.** Владельцу ставится задача «WhatsApp отключился:
  <филиал>». Пока номер не подключён заново, сообщения идут другими
  каналами (push, email). Раз в 10 минут CRM сверяет статусы номеров с
  Evolution на случай, если событие об отключении потерялось.

## Где это в CRM

| Экран | Что |
|---|---|
| Рассылки → Настройки → WhatsApp | Номера по филиалам, «Подключить номер» (QR-код), статус, «Отключить». Официальный API Meta — свёрнутая кнопка ниже. |
| Колокольчик → «WhatsApp» | Сколько переписок ждут ответа и кто написал последним; по клику — карточка родителя или заявки с чатом. Пропадает, когда ответили с номера центра. Видят владелец, управляющий, администратор. |
| Карточка родителя → «Коммуникации», карточка заявки | Чат WhatsApp: входящие слева, ответы сотрудников и автоматические напоминания справа, со статусами; поле ответа внизу. В обе стороны — фото, голосовые и аудио, видео, документы (отправка до 16 МБ; аудио уходит голосовым). Ниже — «Заметки»: звонки и комментарии с файлами (до 5 по 10 МБ); у родителя видны и в карточках его детей. Переписка в заметки не копируется. |
| Рассылки → Журнал (фильтр по родителю) | Что ушло, статусы «Доставлено» и «Прочитано», ответ родителю обычным текстом. |
| Долги, Продления → «Напомнить в WhatsApp» | Массовая отправка выбранным, с какого номера уйдёт. |
| Автоуведомления | Абонемент заканчивается, долг, отмена и перенос, напоминание о занятии — через канал WhatsApp в общем порядке каналов. |
| Объявления → «Опубликовать» | Семьям из аудитории объявления (центр, филиал, направление, группа) — заголовок, текст и ссылка на кабинет; одной семье один раз, просроченное не уходит. |
| Кнопки «WhatsApp» — заявка, родитель, контакты ребёнка, задачи, долги, продления, отток, риск ухода, тексты ИИ | Окно с готовым текстом → «Отправить» с номера центра (владелец, управляющий, администратор). Сообщение — в журнале, в истории заявки или карточке ребёнка. Нет номера по QR или роль другая — открывается свой WhatsApp, как раньше. |

Писать с номера центра можно только своим родителям и заявкам (номер ищется в
CRM) — номер центра не шлюз для любых номеров. Пароль от кабинета родителя по-прежнему
отправляется со своего WhatsApp: через номер центра он остался бы открытым
текстом в журнале.

Незнакомый номер написал — создаётся заявка с источником «WhatsApp» в
филиале номера, имя — как подписан человек в WhatsApp. Группы, рассылки,
статусы, реакции и история чатов, подтянутая при подключении, в CRM не
попадают.

## Запуск на сервере

1. База для Evolution в том же Postgres (один раз):

       docker compose -f docker-compose.staging.yml exec db createdb -U kidscrm evolution

2. Настройки Evolution:

       cp infra/evolution/.env.example infra/evolution/.env

   Заполнить `AUTHENTICATION_API_KEY` (`openssl rand -hex 32`) и пароль
   Postgres в `DATABASE_CONNECTION_URI`.

3. В `backend/.env`:

       EVOLUTION_API_URL=http://evolution:8080
       EVOLUTION_API_KEY=<тот же ключ>

   `PUBLIC_BASE_URL` должен быть настоящим адресом сайта — на него
   Evolution шлёт события.

4. Запуск и миграции:

       docker compose -f docker-compose.staging.yml up -d --build
       docker compose -f docker-compose.staging.yml exec backend python manage.py migrate

5. В CRM: Рассылки → Настройки → WhatsApp → выбрать филиал →
   «Подключить номер» → отсканировать QR-код телефоном (WhatsApp →
   Настройки → Связанные устройства → Привязать устройство).

## Локально

    docker compose exec db createdb -U kidscrm evolution
    docker compose --profile whatsapp up -d evolution

В `backend/.env`:

    EVOLUTION_API_URL=http://evolution:8080
    EVOLUTION_API_KEY=dev-evolution-key
    EVOLUTION_WEBHOOK_BASE_URL=http://backend:8000

## Что важно помнить

- **Номер могут заблокировать.** Для пилота — отдельный номер, не основной.
  Не отправлять рекламу людям без согласия и не уменьшать паузу
  `EVOLUTION_SEND_INTERVAL`.
- **Телефон с номером** должен время от времени выходить в интернет, иначе
  WhatsApp отвяжет устройство (примерно через 14 дней без связи).
- **Обновление Evolution** — менять тег образа осознанно, после проверки на
  стенде. Версии до 2.3.7 включительно имеют уязвимость в `/metrics`
  (CVE-2026-91997) — у нас метрики выключены и порт не открыт.
- **Лицензия** требует, чтобы в системе было видно, что используется
  Evolution API, — подпись в настройках WhatsApp не убирать.
