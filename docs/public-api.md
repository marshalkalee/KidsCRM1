# Публичное API KidsCRM, версия 1

Для тарифа Enterprise (ТЗ п. 10.1, п. 12; TRU-176). Внутренний API
(`/api/v1/`) меняется вместе с нашим фронтендом. Публичный —
обязательство перед чужим кодом, поэтому живёт отдельно
(`/api/public/v1/`) и меняется только по правилам ниже.

Документация, сгенерированная из кода: `/api/public/v1/docs/`, схема
OpenAPI: `/api/public/v1/schema/`.

## Что открыто в v1

| Метод | Адрес | Что | Фильтры |
|---|---|---|---|
| GET | `children/` | Дети: имя, дата рождения, статус, группы | `status` |
| GET | `groups/` | Группы: филиал, направление, вместимость, возраст | — |
| GET | `lessons/` | Занятия за период | `date_from`, `date_to` (обязательны, до 62 дней), `group` |
| GET | `attendance/` | Отметки посещаемости за период | `date_from`, `date_to`, `child` |
| GET | `subscriptions/` | Абонементы: название, срок, статус, остаток занятий, цена | `status`, `child` |
| GET | `payments/` | Оплаты за период | `date_from`, `date_to`, `child` |
| POST | `leads/` | Новая заявка в воронку (источник «Интеграция (API)») | — |

Списки постраничные: `limit` (по умолчанию 100, максимум 500) и `offset`;
в ответе `count`, `next`, `previous`, `results`.

**Чего нет намеренно:** телефонов и контактов родителей, медицинских
заметок, причин ухода, скидок и комментариев сотрудников. Ключ попадает в
чужой код и логи, персональные данные детей без нужды наружу не отдаём
(ТЗ п. 10.3). Отметка посещаемости через API — не в v1: ошибка в чужом
скрипте списала бы занятия у всего центра.

## Ключ

Выдаёт владелец центра: «Настройки → API-ключи». Ключ показывается **один
раз** — у нас хранится только его хеш.

    Authorization: Bearer kc_live_…
    # или
    X-Api-Key: kc_live_…

- **Область:** «только чтение» или «чтение и запись» (заявки).
- **Филиалы:** все или выбранные — ключ видит детей, группы, занятия,
  абонементы и оплаты только этих филиалов.
- Ключ не сильнее сотрудника: у него нет доступа к контактам родителей,
  деньгам сверх перечисленного, настройкам и сотрудникам.
- Отзыв — одной кнопкой, действует сразу.
- Каждое обращение в журнале: ключ, время, адрес, ответ, IP.

## Лимиты

60 запросов в минуту и 20 000 в сутки на ключ. Сверх — `429 Too Many
Requests` с заголовком `Retry-After` (через сколько секунд повторить).

## Ошибки

| Код | Когда |
|---|---|
| 400 | Неверные параметры; тело — `{"поле": ["что не так"]}` |
| 401 | Нет ключа, ключ неверный или отозван |
| 403 | Тариф не Enterprise или у ключа только чтение для записи |
| 429 | Лимит; смотрите `Retry-After` |

## Совместимость: что считается ломающим

В v1 **можно без новой версии:**

- добавить новый адрес;
- добавить поле в ответ;
- добавить необязательный параметр запроса;
- добавить новое значение статуса (клиент должен быть готов к незнакомым
  значениям).

**Ломающее — только в v2:**

- убрать или переименовать адрес, поле или параметр;
- поменять тип или смысл поля;
- сделать необязательный параметр обязательным;
- ужесточить лимиты или проверку значений.

Новая версия объявляется центрам с Enterprise письмом минимум за 3 месяца;
v1 работает ещё 6 месяцев после выхода v2.

## Примеры

    curl -H "Authorization: Bearer kc_live_…" \
      "https://app.kidscrm.kz/api/public/v1/lessons/?date_from=2026-10-01&date_to=2026-10-31"

    curl -X POST -H "Authorization: Bearer kc_live_…" -H "Content-Type: application/json" \
      -d '{"parent_name":"Айгерим","phone":"+77071112233","child_name":"Алия","child_age":6}' \
      https://app.kidscrm.kz/api/public/v1/leads/

## Для разработчиков

- Код: `backend/domains/platform/public_api/`. Новый адрес — в
  `urls.py → data_patterns` и обязательно в `tests.py → ISOLATION`:
  тест изоляции тенантов блокирующий в CI и падает, если адрес не покрыт.
- Ответ — только через сериализаторы `public_api/serializers.py` с явными
  полями; внутренние сериализаторы сюда не подключать.
- Тариф: `tenants/plans.py → "public_api"`; без явного тарифа Enterprise
  ключ не работает.
