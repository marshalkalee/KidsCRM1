# KidsCRM — что сделано и что нужно обсудить

Сводка для разговора в конце проекта: что сделано и что осталось решить с
владельцем True Ballet, начальником или командой. Файл живой: когда задача
доделана, а в ней остался вопрос, который не решить кодом, вопрос
дописывается сюда, а тикет закрывается со ссылкой на этот файл.

**Как пополнять**

- Новый вопрос — строка в таблицу «Нужно обсудить» с датой, тикетом и тем,
  кто решает. Решённый вопрос не удаляем: переносим в «Решено» с ответом.
- Сделанное — в раздел «Сделано» нужного блока, с номером тикета и PR.

## Решено

| Вопрос | Решение | Когда |
|---|---|---|
| Выручка — по дате оплаты или размазывать по сроку абонемента | По дате оплаты (ТЗ «выручка по оплатам»), подписано на экране и в выгрузке. Отменённая оплата уменьшает выручку дня, когда её принимали. | 30.09.2026 |
| «Не пришёл на пробное» — отказ или нет | Потеря контакта, считается отдельно от возражений; признак причины `is_lost_contact`, работает и после переименования. | 30.09.2026 |
| Большие выгрузки — фоновой задачей? | Не нужно: отчёты выгружают агрегаты, год на 5000 детей — 0,7–3 с, файл до 20 КБ. | 30.09.2026 |
| Организация с одним филиалом в «Сравнении филиалов» | Экран показывается: одна строка и пояснение «сравнивать не с чем». | 30.09.2026 |
| Когда удалять старый серверный веб (TRU-88) | Удалён 01.10.2026 по решению Анель: все экраны во frontend2, проверки прав, изоляции и скорости перенесены на API, старые адреса перенаправляются на новые экраны. | 01.10.2026 |
| Долг родителя — только где плательщик или по всем детям | По всем привязанным детям (как карточка родителя), записано в контракте №5. | 30.09.2026 |

## Сделано

### Деньги
- **TRU-61** пересчёт остатка занятий по кнопке, отчёт о расхождениях — PR #105.
- **TRU-62** один расчёт «заканчивается», дата центра вместо даты сервера — PR #105.
- **TRU-63** заморозка: понятные ошибки, досрочная разморозка, история — PR #105.
- **TRU-67** «Принять оплату» во frontend2: сумма = долг, Kaspi первым, без двойных оплат — PR #105.
- **TRU-68** экран «Задолженности», выгрузка в Excel — PR #105.
- **TRU-69** экран «Продления», продажа продления из экрана — PR #105.
- **TRU-73** один расчёт долга, второй удалён — PR #109.
- Продажа абонемента во frontend2 не работала (500) — починено в PR #105.
- **Удалённая оплата через Kaspi**: в окне «Принять оплату» — «Счёт в Kaspi». Счёт родителю на телефон, сообщение для WhatsApp, счета в ожидании во вкладке «Оплаты», «Оплата пришла» / «Отменить»; долг уменьшается только после оплаты. Задел под автоматический Kaspi (шлюз, вебхук, тестовая страница оплаты). См. ADR-003, п. 16 «Нужно обсудить».

### Продажи
- **TRU-98** продления — отдельная воронка (PR #95), продажа закрывает заявку-продление (PR #108), автоправило «абонемент заканчивается → заявка-продление» (PR #114).

### Платформа и frontend2
- **TRU-78** переезд веба на frontend2: все экраны перенесены (подзадачи TRU-79…TRU-92 закрыты).
- **TRU-88** старый серверный веб удалён: шаблоны, статика, веб-вьюхи, веб-вход, djlint; проверки прав, изоляции тенантов и скорости перенесены на API; старые адреса ведут на новые экраны.

- Вход не работал, если в браузере остался токен отключённого пользователя — PR #119.
- develop не собирался после слияния #102 (пропущенная запятая в переводах) — исправлено в PR #116.
