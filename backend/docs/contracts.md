# Контракты между доменами

## Статус

Черновик. Контракты ниже описаны по постановке задачи и зафиксированы в
коде как интерфейсы + заглушки, чтобы никто не ждал чужой реализации.
Финальное подтверждение — созвон троих (Bekzat, Дарья, Анель): все должны
одинаково понимать границы, до того как M1 начнётся всерьёз.

## Зачем

Домены поделены так, чтобы пересекаться минимально, но четыре точки стыка
есть в любом случае. Если их не описать до начала M1 — они превратятся во
взаимные блокировки в середине спринта. Договариваемся об интерфейсах на
бумаге и в коде, до того как заработала реальная логика с обеих сторон.

## Правило изменений

У каждого контракта один владелец. Менять сигнатуру или семантику статусов
можно только через PR, где владелец — обязательный ревьюер. Потребитель
кодирует свою сторону против интерфейса (`ABC`) и заглушки (`Stub...`) ниже,
а не против внутренностей чужой реализации — когда реальный сервис будет
готов, потребитель меняет только импорт (`Stub...Service` → `...Service`),
не свой код вокруг вызова.

## 1. Расписание → Деньги

​```python

SubscriptionService.consume(child_id: UUID, lesson_id: UUID, direction_id: UUID) -> ConsumeResult

​```

Вызывается при отметке посещения «пришёл» — списывает занятие с активного

абонемента ребёнка. `direction_id` добавлен намеренно: при нескольких

активных абонементах ребёнка (разные направления) без него нет способа

выбрать правильный (см. TRU-58/59, Subscription.direction). Обновлено до

появления первого вызывающего кода (TRU-50) — без обратной несовместимости.

`ConsumeResult.outcome` различает пять исходов: `CONSUMED`,

`NO_ACTIVE_SUBSCRIPTION`, `SUBSCRIPTION_EXHAUSTED`, `SUBSCRIPTION_FROZEN`,

`RULE_FORBIDS`. Все пять — ожидаемые бизнес-исходы, не исключения.

Владелец: **Bekzat**. Потребитель: **Дарья**.

## 2. Люди → Деньги и Продажи

```python
ChildService.find_duplicates(phone: str) -> list[Child]
ChildService.create_with_parent(child_full_name, child_birth_date, parent, branch_id) -> Child
```

Нужно и для импорта Excel (ТЗ п. 4.1 — дубли выявляются при импорте), и для
конвертации заявки (ТЗ п. 5.1 — «Пришёл на пробное» создаёт или связывает
существующего ребёнка). Поиск дублей — обязанность вызывающей стороны:
сначала `find_duplicates`, затем осознанное решение создавать новую запись
или связать с найденной.

Владелец: **Анель**. Потребители: импорт Excel, домен «Продажи».

## 3. Расписание → всем

```python
LessonService.enroll(lesson_id: int, child_id: int, kind: EnrollKind) -> EnrollResult
```

`kind = MAKEUP | TRIAL` — один механизм обслуживает и отработки (M1), и
пробные занятия (M2). Контроль вместимости обязателен: переполненное
занятие — это `LESSON_FULL`, а не исключение. Право ребёнка на отработку
(есть ли абонемент, не истёк ли срок) сервис не проверяет — это делает
вызывающая сторона до вызова `enroll`.

Владелец: **Дарья**. Потребители: все домены (в первую очередь «Деньги» —
отработки, «Продажи» — пробные).

## 4. Деньги → всем

```python
AuditLog.record(actor, action: str, entity: AuditEntity, before: dict | None, after: dict | None) -> None
```

Один общий сервис вместо трёх копий в трёх доменах (ТЗ п. 2 — аудит-лог
изменений оплат, посещений, абонементов). `action` — namespaced строка вида
`"domain.verb"` (`"payments.update"`, `"attendance.edit_backdated"`);
реестр допустимых действий ведут вызывающие домены, не владелец интерфейса.
Код лежит в `apps/core`, а не в `apps/payments` — сервис общий, хотя
интерфейс принадлежит домену «Деньги».

Владелец: **Bekzat**. Потребители: все домены.
