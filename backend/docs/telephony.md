# Телефония (TRU-174)

Первый production-адаптер — **Zadarma**: у провайдера есть виртуальная АТС,
webhook-события и API записей, а казахстанский номер можно подключить после
проверки доступности и требований к документам у провайдера. Доменный слой не
зависит от формата Zadarma: провайдер переводит события в единый контракт
`CallRecord`, поэтому позже можно добавить UIS/OnlinePBX без изменения CRM.

## Режимы

- `console` — локальная разработка и CI. Кнопка звонка открывает `tel:`;
- `zadarma` — production-подключение после выдачи центром API key/secret и
  виртуального номера. При недоступности АТС интерфейс также использует `tel:`.

Настройка и журнал находятся на `/messaging?tab=calls`. Webhook:
`/api/v1/messaging/telephony/webhook/<secret>/`.

## Контракт webhook

POST JSON: `call_id`, `phone`, `direction`, `status`, `started_at`,
`answered_at`, `ended_at`, `duration_seconds`, `result`, `employee_id`,
`recording_url`, `recording_expires_at`.
Повтор одного события безопасен: ключ `(organization, call_id)` уникален.

## Записи и персональные данные

Аудио в KidsCRM не копируется — хранится только временная ссылка провайдера.
Запись включается владельцем только после подтверждения предупреждения
звонящего. Доступные роли задаются организацией; каждое открытие ссылки
фиксируется в `AuditLog` как `play_call_recording`. Преподавателю записи
недоступны. Срок хранения и текст предупреждения центр согласует с юристом и
провайдером до production-включения.

## Автоматизация

- известный номер связывается с родителем, ребёнком или заявкой;
- неизвестный номер превращается в заявку с источником «Звонок» вручную;
- пропущенный входящий создаёт одну открытую задачу «перезвонить» на номер;
- завершённый звонок известному ребёнку попадает в `CommunicationLog`.
