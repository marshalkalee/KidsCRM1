# Доменная структура backend

Код разбит по доменам, а не по слоям (не `models/`, `views/`, `serializers/`
на весь проект) — это то же деление, по которому распределены люди в команде.
Чем реже два человека трогают один файл, тем меньше конфликтов при слиянии.

| Домен | Приложения | Владелец |
|---|---|---|
| [`people`](people/) | `clients` | Анель |
| [`scheduling`](scheduling/) | `schedule`, `attendance` | Дарья |
| [`money`](money/) | `subscriptions`, `payments` | Bekzat |
| [`platform`](platform/) | `core`, `tenants`, `users`, `notifications`, `tasks`, `leads` | общий фундамент — используется всеми доменами, правки — по согласованию, а не в одиночку |

Каждое приложение — обычное Django-приложение, зарегистрированное в
`INSTALLED_APPS` (см. `config/settings/base.py`) под полным путём
`domains.<домен>.<приложение>`, с коротким уникальным `label` в `apps.py`
(само имя приложения, без домена в label — конфликтов между доменами по
`label` не будет, так как имена приложений внутри одного проекта не
повторяются).

## Правила

- Приложение живёт только в своём домене. Если новой функциональности не
  находится места ни в одном домене — это повод завести домен/приложение,
  а не размазывать код по существующим не по смыслу.
- Контракты на стыке доменов (кто зовёт чей сервис) описываются явно —
  см. `docs/contracts.md` (переносится сюда из ветки с контрактами при
  слиянии) и докстринги в `services.py` каждого приложения.
- `platform` — общий фундамент (мультитенантность, пользователи/роли,
  уведомления, задачи, заявки). Правки в нём затрагивают все домены —
  согласовывать перед мержем, а не мержить в одиночку.

## Веб (шаблоны и статика)

Веб — серверный рендеринг, без SPA (см. ADR-002). Шаблоны и JS конкретного
домена организованы тем же делением, чтобы конфликты на статике были не
чаще, чем в Python-коде:

- `backend/templates/<домен>/*.html` — страницы домена, наследуются от
  `backend/templates/base.html`.
- `backend/static/site/js/domains/<домен>.js` — JS, специфичный для страниц
  домена (не трогать чужой файл).
- `backend/static/site/js/vendor/` — сторонние библиотеки (jQuery,
  Bootstrap, Select2, DataTables, FullCalendar и т.д.), без сборщика,
  подключаются `<script>`-тегами. Версии и что нужно докинуть — см.
  `vendor/README.md`.
- `backend/static/site/css/kc.css` — общая design-system (`.kc-*`), правки
  в ней затрагивают все домены — согласовывать, как и правки в `platform`.
- i18n: словари — `backend/i18n_src/{ru,kk,en}.json`, бандл для браузера
  собирает `backend/scripts/build_i18n_bundle.py`, обёртка на странице —
  `window.KidsCRM.t()` (см. `static/site/js/i18n.js`).
