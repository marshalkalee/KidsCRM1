# Соглашение о ветках, коммитах и PR

## Ветки

`<тип>/<короткий-слаг>`, тип — один из:

- `feature/...` — новая функциональность (`feature/attendance-checkin`)
- `fix/...` — исправление бага (`fix/subscription-remaining-count`)
- `docs/...` — документация, ADR (`docs/adr-003-...`)
- `chore/...` — инфраструктура, зависимости, конфиги без изменения поведения

Для задач, привязанных к ADR или тикету, слаг включает номер:
`feature/ADR-002-stack-repo-api` (см. существующие ветки в репозитории).

Ветки короткоживущие — от `main`, мерж обратно в `main` через PR.

## Коммиты

[Conventional Commits](https://www.conventionalcommits.org/), scope —
домен, который затронут (`people`, `scheduling`, `money`, `platform`),
либо `web`, если правка про шаблоны/статику/design-system, не привязанные
к одному домену (например, правка `kc.css` или i18n-бандла):

```
<тип>(<scope>): <описание в повелительном наклонении, по-русски>
```

Примеры:

```
feat(scheduling): добавить перенос занятия с указанием причины
fix(money): не списывать занятие при повторной отметке посещения
docs: ADR-003 — модель ролей и прав доступа
chore: обновить зависимости backend
```

Типы: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`.

## Pull Request

- Один PR — одна логическая единица работы; не смешивать домены без
  причины (если PR трогает 2+ домена — это повод проверить, не размыты
  ли границы, см. `backend/domains/README.md`).
- PR обязан пройти `pre-commit run --all-files` до запроса ревью.
- Шаблон PR подтягивается автоматически — заполнить все пункты
  ([`.github/PULL_REQUEST_TEMPLATE.md`](.github/PULL_REQUEST_TEMPLATE.md)).
- Правки в `platform`-домене (общий фундамент, см. `backend/domains/README.md`)
  и в контрактах между доменами (`docs/contracts.md`) требуют ревью от
  владельца затронутого контракта, а не только от кого-то одного.
